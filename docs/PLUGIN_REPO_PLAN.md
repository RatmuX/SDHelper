# Plugin Repository Plan: `RatmuX/SDHelper-Plugins`

Planning only. The repository is created after the owner approves.

## 1. Repository layout

```
SDHelper-Plugins/
  README.md                  what this is + "How to write a plugin" quick start
  docs/creating-a-plugin.md  step-by-step guide (manifest, actions, params, testing)
  docs/permissions.md
  spec/                      JSON Schema for plugin.json + validator CLI
  sdk/kotlin/  sdk/python/  sdk/node/
  template/                  starter plugin per language
  plugins/                   community catalog (one folder per plugin)
  CONTRIBUTING.md  SECURITY.md  CODE_OF_CONDUCT.md  LICENSE
```
One repository for now. Split `sdk` or `spec` into their own repositories only when they get independent release cadences.

## 2. Versioning and compatibility
- SemVer for the spec, each SDK and each plugin.
- A compatibility matrix maps plugin spec version to supported SDHelper protocol versions and app versions.
- The reference copy of the spec lives in the main repo (`core:plugin-api`); the plugins repo pins to a released spec version.

## 3. CI
- Validate every `plugin.json` against the schema.
- Lint, run SDK tests, check that the template works.
- Secret scanning on pull requests.

## 4. Catalog and review policy
- Contributions by pull request into `plugins/<id>/` with source (no opaque binaries in the catalog).
- Reviewer checklist: declared permissions match code behavior, no obfuscation, license present, no network use without `net`.
- Signing idea for later: release artifacts signed (for example Sigstore); the app verifies signatures before install.
- In-app catalog discovery: the app fetches an index file generated by CI from `plugins/`.

## 5. Contributor docs
The README has a short "write your first plugin in 5 minutes" section that links to the full guide, so third parties can start without reading the app source.

## 6. What stays in the main repo
App, agent, protocol, `core:plugin-api`, built-in plugins and the reference spec. The plugins repo holds only third-party material, the SDKs, the template and the catalog.
