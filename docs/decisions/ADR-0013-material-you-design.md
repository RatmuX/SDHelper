# ADR-0013: Material You 3 design and the new app skeleton

**Context.** The owner had the design made by another tool and gave it as HTML references (`material-you-3/`, `miuix/`) with a handoff document. The files are visual specifications, not code: they are never copied, shown in a WebView or turned into Compose by translating CSS classes. Only the look, the information hierarchy, the states and the interaction intent are taken. The design changes the structure of the app, not only its colors, so it comes before the plugin system (phase 4), whose screens would otherwise be built on the old skeleton and redone.

**Decisions.**
- **Material You 3 only in this phase.** Miuix is the first update after v1.0 (owner's decision); the General screen shows its row marked "coming soon", and that row does not react to touch.
- **Static palette from the references** (indigo, light and dark). Roles the references do not define (tertiary, error, lowest and dimmed surfaces, inverse colors) were chosen to match and are marked as such in `M3Palette`. Shapes and type scale of the references equal the Material 3 defaults, so only colors needed overriding. Dynamic color is not used (the design does not ask for it).
- **Theme is a setting.** `ThemeMode` SYSTEM (until the person picks), LIGHT, DARK, stored in `data:settings`; `DeckTheme(design, darkTheme)`. It applies at once from Settings > General.
- **Home is a frame with a navigation drawer** (`AppMode`: Stream Deck, Touch Pad, Keyboard). The drawer shows the connected computer (name, address from the paired computer; "Connect a computer" otherwise, which opens the connection screens) and the settings gear at the bottom. The last mode is restored. Touch Pad and Keyboard are shown with a "coming soon" badge and are **inert**: no click handler, no ripple, announced as unavailable; they cannot be selected, and a stored unavailable mode opens the Stream Deck. This replaces the `Surface` model.
- **Settings are one list** (Stream Deck, Touch Pad and Keyboard marked coming soon, General last). Stream Deck settings: vibration, keep screen on, and the saved layouts (use, rename, copy, delete; the last one cannot be deleted). General: design and light/dark.
- **The control panel has no bars at all.** Only the buttons and, at the bottom, the page dots with "Page name · 1 / 2". Layout switching moved out of it. A short message appears on top only when something needs saying (not connected, a refusal). Tile look follows the reference (tonal low surface, active = primary container, hint line = live label); icons are our vector icons, not the placeholder letters.
- **The editor is the control panel with numbered cells** and one "Ready-made settings" pill in the corner. Its menu: the list of layouts (check on the active one), **Save** (a copy under a name; edits are saved at once anyway), **New** (empty or from a ready-made layout, under a chosen name), **Name it** (rename the current one). Page and grid-size entries are not in the references and were added to the same menu in the same look. First start creates Default, Streaming, Meeting and Gaming layouts (Default active).
- **`LayoutManager`** (`core:model`) holds layout management for both the editor and the settings; the screens pass in language dependent texts.
- **Screens without a reference** (connection screens, Stream Deck settings, dialogs) use the same components and look: grouped rows, text actions and tonal pills, 28dp dialogs. Buttons in the design language are the secondary-container pill and the plain text action; filled and outlined buttons are not used.
- **Contract growth.** `design-api` gained the drawer shell, settings group and rows, choice rows, segmented choice, feature card, pill and popup menu; `Card` and `SwitchRow` were removed as unused.

**Not verified.** Everything visual and gestural (drawer animation, popup placement in the immersive landscape screens, the segmented control borders, dark-theme contrast, drag in the editor) runs only on the owner's phone; the logic (settings, home state, layouts, presets, bootstrap) is covered by unit tests. Pixel equality with the HTML is not promised.
